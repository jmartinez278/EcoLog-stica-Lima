## 4. Estrategia de Gestión y Comunicación

| Interesado / Grupo | Frecuencia | Formato | Información principal | Responsable |
|---|---|---|---|---|
| Gerencia / Patrocinador | Semanal | Reunión de seguimiento + reporte ejecutivo | Avance, riesgos, decisiones, presupuesto y próximos hitos | Director de Proyecto |
| Área de Operaciones | Semanal o quincenal | Reunión funcional + demo | Reglas de negocio, restricciones operativas, resultados del algoritmo | Director de Proyecto |
| Equipo docente | Al cierre de cada iteración y según calendario académico | Entregable formal + demo/presentación | Cumplimiento de consigna, rúbrica, avance y evidencias | Director de Proyecto |
| Equipo de desarrollo | Diaria y semanal | Stand-up + tablero Kanban | Tareas, bloqueos, dependencias y avance técnico | Director de Proyecto / Equipo |
| Conductores | Cuando existan incrementos del modo conductor | Demo + encuesta o entrevista | Usabilidad, claridad de ruta, alertas y experiencia de uso | Equipo del proyecto |
| Clientes finales | En validaciones de requisitos o aceptación | Encuesta, entrevista o escenario simulado | Preferencias de entrega, ventanas de tiempo y nivel de servicio | Equipo del proyecto |
| Proveedor tecnológico | Según necesidad | Ticket, documentación o correo | Disponibilidad, límites, costos y cambios de API | Responsable técnico |
| Autoridades aplicables | Cuando exista consulta normativa | Comunicación formal | Restricciones viales, normativas o de operación | Director de Proyecto |
| Comunidad / programas ambientales | Ocasional | Nota informativa o reporte | Impacto ambiental, seguridad y compensación | Equipo del proyecto |

## 5. Estrategia por Cuadrante

| Cuadrante | Estrategia |
|---|---|
| Gestionar de cerca | Involucrar en decisiones clave, revisiones, priorización y aceptación. |
| Mantener satisfecho | Comunicar cambios relevantes y solicitar validación cuando exista impacto técnico o normativo. |
| Mantener informado | Proporcionar avances frecuentes, demos y mecanismos de retroalimentación. |
| Monitorear | Revisar cambios en expectativas o influencia y comunicar solo información relevante. |

## 6. Principios de Participación

- Comunicar la información adecuada según el nivel de poder e interés.
- Registrar acuerdos que afecten alcance, costo, tiempo o calidad.
- Involucrar tempranamente a usuarios operativos en validaciones.
- Escalar conflictos o expectativas que comprometan los objetivos del proyecto.
- Revisar la matriz de poder/interés cuando cambie la influencia de un interesado.

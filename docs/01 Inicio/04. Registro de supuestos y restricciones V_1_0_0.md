|---|---|---|---|---|

| C2 | El presupuesto inicial máximo del MVP es de S/ 500,000. | Costo | Alta | Baja — corresponde a RES-05 de la consigna. |
| C3 | El algoritmo debe producir una solución válida en ≤ 45 segundos para hasta 150 pedidos y 15 vehículos. | Tecnología | Alta | Baja — requisito no funcional obligatorio. |
| C4 | La re-optimización debe realizarse en menos de 30 segundos ante cambios repentinos. | Tecnología | Alta | Baja — condición de rendimiento definida. |
| C5 | La arquitectura debe poder escalar horizontalmente hasta 1,000 pedidos diarios y 50 vehículos. | Tecnología | Alta | Media — la solución técnica puede variar, pero la capacidad objetivo debe considerarse. |
| C6 | El sistema debe alcanzar 99.5% de disponibilidad en horario operativo de 5:00 AM a 10:00 PM. | Tecnología | Alta | Baja — RNF-06 obligatorio. |
| C7 | La interfaz debe cumplir WCAG 2.1 nivel AA y contemplar usuarios con experiencia tecnológica limitada. | Normativa | Media | Baja — criterio obligatorio de accesibilidad. |
| C8 | El sistema debe aplicar las disposiciones de protección de datos, tránsito y operación vehicular indicadas en la consigna. | Normativa | Alta | Baja — cumplimiento no negociable. |

| C10 | El sistema debe considerar conectividad limitada y funcionar de forma responsive en conexiones de baja velocidad. | Tecnología | Media | Media — la estrategia técnica puede adaptarse. |
| C11 | El sistema debe trabajar con datos georreferenciados y contemplar precisión variable de tráfico en tiempo real. | Tecnología | Alta | Baja — condición esencial del escenario logístico. |
| C12 | Las rutas deben contemplar zonas de riesgo, restricciones de seguridad vial e incidentes reportados. | Normativa | Alta | Media — las fuentes de datos pueden variar, pero el criterio debe ser considerado. |
| C13 | Las rutas deben evitar o minimizar el impacto sobre áreas ecológicas y zonas sensibles cuando aplique. | Normativa | Media | Baja — restricción ambiental definida en el escenario. |

| C15 | El sistema debe considerar condiciones de infraestructura vial, incluyendo vías pavimentadas y no pavimentadas. | Tecnología | Media | Media — la forma de modelarlo puede ajustarse. |

| C17 | La interfaz debe estar adaptada al español peruano y utilizar iconografía universal y lenguaje accesible. | Tecnología | Media | Media — el contenido puede refinarse mediante validación con usuarios. |
| C18 | El sistema debe apoyar un plan de carbono neutral a tres años mediante optimización, migración tecnológica y compensación. | Normativa | Media | Baja — corresponde a una restricción estratégica del escenario. |

## 4. Seguimiento y Control

Los supuestos y restricciones se revisarán al cierre de cada iteración.

- Cuando un supuesto deje de ser válido, deberá registrarse como riesgo, incidencia o solicitud de cambio según corresponda.
- Las restricciones de baja flexibilidad no podrán modificarse sin autorización del nivel de gobernanza correspondiente.
- Los cambios que afecten costo, tiempo, alcance mínimo o calidad deberán analizarse antes de su aprobación.
